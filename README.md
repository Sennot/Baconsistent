# Baconsistent 1.1.0

Форк [Blitzkrieg](https://github.com/ZhulinskiiDanil/blitzkrieg) для Geometry Dash.
База: Blitzkrieg 2.3.5, commit `c25beaedffe55193d0a9e8957836218249923169`.
Исходный мод — Zhulis; метод фиксированных повторений — бекончик.
Лицензия оригинала MIT сохранена в `LICENSE.txt`.

## Что изменено

- Название Baconsistent, отдельный ID `sennot.baconsistent` и отдельные сохранения.
- Фон основной и круглой иконки заменён флагом Казахстана.
- Выбранные стартпозы задают постоянные соседние парты: например,
  `0–10`, `10–20`, `20–30`, …, `90–100`. Они не удлиняются после прохождения.
- В Stage Browser каждый стейдж — отдельный цикл тех же фиксированных партов.
  По умолчанию список идёт с конца уровня; сортировку можно переключать штатной кнопкой.
- В Create Profile и Edit Profile есть **Passes per part**: от 1 до 9999,
  по умолчанию 20. Это общая цель для каждого парта данного профиля.
- Под каждым партом отображается счётчик `7/20` и кнопки **− / +**.
  Минус не уводит ниже нуля. Если уменьшить счётчик ниже цели, парт открывается.
- Штатная галочка остаётся быстрым закрытием парта до цели / открытием на
  один повтор ниже цели. Для точной коррекции используйте −/+.
- Карандаш справа от счётчика открывает **Run Target**: задайте отдельную цель
  для этого рана в выбранном стейдже, например увеличьте 20 до 30. Можно ввести
  число либо использовать −/+ в окне цели. **Save** сохраняет; **Default**
  подставляет общую цель профиля (после этого нажмите Save).
- Цель можно менять у незавершённых, закрытых и временно заблокированных ранов.
  Пример: `7/20` становится `7/30`, а другие раны и стейджи не изменяются.
  Смена общей цели профиля влияет на раны без отдельной цели.
- Смена цели сохраняет все накопленные повторы и пересчитывает завершённость.
- Ручные поправки не добавляют попыток, времени, первых или лучших ранов.
  Pass Rate считается по фактическим игровым прохождениям.

## Стейджи / циклы

1. Закройте все парты текущего цикла по их собственным целям.
2. Нажмите **New Stage** вверху Stage Browser.
3. Новый стейдж получает те же парты, заметки и цели, но счётчики, попытки,
   время, First Clear и Best Run начинаются с нуля.
4. Старые стейджи и их статистика сохраняются. Просмотр — штатными стрелками
   и клавишами переключения стейджей.

Новый цикл создаётся вручную после завершения всех существующих циклов.
Игра засчитывает попытки в первый незавершённый стейдж, независимо от того,
какой стейдж открыт для просмотра. Если всё уже завершено, дополнительные
повторы записываются в последний стейдж до нажатия New Stage.

Если увеличить цель у старого закрытого рана выше набранного количества,
этот стейдж снова откроется. Прогресс более поздних циклов сохранится;
продолжить их можно после закрытия открытого раннего стейджа.

Обновление с 1.0.0 сохраняет ID мода и ваши сохранения: существующий цикл
остаётся первым стейджем, старые раны наследуют цель профиля. Отдельные цели
и все циклы сохраняются в JSON и входят в экспорт/импорт профилей.

## Как засчитывается попытка

Сохранено исходное правило Blitzkrieg: **одна попытка — один выбранный парт**.
Для зачёта нужно начать не позже начала парта и дойти до его конца.
Если начать внутри парта, полное прохождение этого парта не засчитывается.
При выборе цели сохранены исходные приоритеты: незакрытые парты, которые
ран полностью покрывает, затем близость к началу рана.

Например, если 10–20 ещё не закрыт, ран 10–35 даст ему один повтор.
Можно продолжать играть после 20: перезапуск на границе не нужен. Как и в
оригинале, запись выполняется при смерти или завершении уровня, а не каждый
кадр. Ручной рестарт живой попытки до её окончания не является зачётом.
Смерти между успешными попытками не обнуляют прогресс — повторы не обязаны
идти подряд. После достижения цели можно продолжать тренироваться.

Профили, привязки, статистика, интерфейс вкладок, детекторы noclip/speedhack,
уведомления и звуки используют исходный код мода. Изменились только связанные
с новой тактикой данные и элементы управления. Вкладка News и подборка
стартпоз-копий по-прежнему используют сервисы оригинального Blitzkrieg.

Импорт старого JSON-профиля преобразует его первый этап в фиксированные
соседние парты, сохраняя статистику совпадающих диапазонов. Старые длинные
этапы не переносятся. Сохранения установленного Blitzkrieg автоматически
не затрагиваются. Исходный граф этапов показывает циклы тренировки и, как
в оригинале, доступен после завершения минимум трёх стейджей.

## Получить .geode для Windows

Требования этой базы: **Geometry Dash 2.2081, Geode 5.10.1**.
Зависимости: `cvolton.level-id-api` и `geode.node-ids`.

1. Поместите содержимое папки Baconsistent в корень своего GitHub-репозитория,
   включая папку `.github`.
2. Откройте **Actions → Build Baconsistent Windows → Run workflow**.
   Сборка также запускается при push.
3. Скачайте артефакт **Baconsistent-Windows**, распакуйте его и установите
   `sennot.baconsistent.geode` через Geode либо поместите в `geode/mods`.

В этом архиве находятся исходники, а не готовый бинарный `.geode`.
Windows-сборка и запуск в Geometry Dash в этой среде не выполнялись.

## Проверка логики

`python3 tests/run.py` запускает C++23-проверки генерации партов, порога
повторов, ручных поправок, изменения цели, импорта и настоящего тела
`GlobalStore::checkRun` с заглушками только для окружения игры и уведомлений.
Проверены продолжение длинного рана, неудачные попытки, старт внутри парта,
достижение 100%, отдельные цели, повторные циклы, сохранение старой статистики,
повторное открытие предыдущего стейджа и независимый зачёт между циклами.
Это не заменяет проверку интерфейса и хуков в игре.
